name: cagoule
description: Discover, deploy, modify and run open-weight models on Cagoule as Modelpack apps. Use when the user wants a model, LoRA, generated media, or a variant of an existing deployment.

Use the installed `cagoule` CLI through local command execution. Use `--json` for structured results and `cagoule COMMAND --help` for current arguments. The plugin contains guidance, not an executable.

On first use in a task, locate `cagoule` on PATH. If missing and Homebrew is available on macOS/Linux, install with `brew install anorak-games/cagoule/cagoule`. Installation and relevant CLI upgrades are authorized as part of using this skill; follow the host's execution permissions without asking for separate skill-level confirmation. Do not install Homebrew itself automatically. For Windows or a manual installation, download the matching OS/architecture archive from https://github.com/anorak-games/homebrew-cagoule/releases/latest, verify it against the release's SHA256SUMS, and place the executable on PATH. Native Windows supports the CLI but not `cagoule shell`; use WSL for shell workflows.

Run `cagoule --json version --check`. A newer version alone does not require upgrading. Upgrade when a requested command is missing, a relevant fix is available, or a compatibility failure calls for it. For Homebrew use `brew update && brew upgrade cagoule`; for manual installations use the verified release archive. Do not replace development builds automatically. If the version check is unavailable, say so and continue if the task can proceed. Recheck the version after upgrading. Old versions that lack `--check` can be identified with `cagoule --version`; upgrade when needed. Do not repeatedly retry a failed installation or upgrade without addressing its reported cause.

Run `cagoule --json status`. If authentication is required, run `cagoule login` once and allow the user to complete browser sign-in while the command waits. Do not request tokens or credentials. Access-denied errors need administrator attention; do not repeatedly reopen sign-in.

An app is a directory containing `modelpack.yml`. That one file declares everything: name, short description, inline Markdown long_description and usage, tags, base_model family, source_url for the implementation repository, an optional experimental flag, the platform stack family, the build command, the command that serves requests, machine types and memory, the Hugging Face volumes it reads, and JSON Schemas for inputs and outputs. The platform derives every deployment setting from it; there is no separate recipe, and the platform does not keep or export app source. Provide concise listing text, factual model capabilities, and practical usage guidance in the manifest. Use a stable family such as h3 or ltx for base_model; source_url links to the app's own source directory, not the upstream project it is derived from; that upstream is recorded in the app's `README.md`. Set `experimental: true` while the app is not ready to depend on: it may not be in a good working state and its inputs and outputs may change frequently. The web UI hides experimental apps from the model library behind a toggle, so use it for a new or in-flux app whose schema is still moving, and clear it in a later revision once the app settles. Weight repositories and pinned revisions belong in volumes.

App directories belong in the catalog, `https://github.com/anorak-games/cagoule-catalog`: one self-contained directory per app at the repository root, named exactly as the app, with source_url pointing at that directory on the default branch. The platform does not keep or export app source, so the catalog is where a deployed model is read, fixed and republished from later; the outcome to avoid is a running model whose source exists only on one laptop. This is a preference about where the source ends up, not a precondition for deploying. Work in a catalog clone, package and publish from the working tree as often as the model needs, and once it behaves, open a pull request to the catalog so the directory lands on the default branch. Nothing in packaging or publishing checks git state, and catalog changes go through review anyway, so do not ask the user to commit or push before a deploy. Follow the neighbouring directories rather than inventing a layout: a `README.md` stating what the model does and how it actually behaves, with a Provenance section naming the upstream implementation repository and commit, the weight repositories and revisions, and any upstream files modified (`modelpack.yml` stays the authoritative pin), vendored upstream code under `upstream/`, model code in a runtime package beside `app.py`, and a `tests/` suite the build command runs so a broken app fails packaging instead of publication. Keeping the source elsewhere is fine when it genuinely lives elsewhere, such as an app already in a repository the user maintains; source_url should still resolve to it.

1. Run `cagoule capabilities` and `cagoule --json apps`. CLI list commands collect pages; when using `cagoule api` directly, follow next_cursor even when a filtered page is empty. `cagoule --json describe APP` returns the current revision including its generated definition and input/output schemas; `cagoule run` handles all models.
2. For a new model, `cagoule hf search` and `cagoule hf inspect` to choose files. Prefer weights the platform has already replicated: `hf inspect` returns a `replicated` list for the repository and `cagoule --json volumes` shows every replicated selection with the apps using it; pinning one of those revisions with the same or a subset of its files publishes in minutes and adds no storage, so only pin a new revision when the model needs it. Then use `cagoule new` with a new directory at the root of a catalog clone, an explicit stack family from `cagoule capabilities` (for example python312-pytorch290-cu130), a machine type and runtime memory. It scaffolds `modelpack.yml`, a self-contained `app.py`, `pyproject.toml` and `.inferignore`; read a sibling directory for the rest of the layout. For a variant of an existing app, follow that app's source_url from `cagoule --json describe APP` to its directory, copy it to a sibling named for the variant, change `name` in `modelpack.yml`, and edit from there so the base and the variant stay side by side and diffable.
3. Edit `modelpack.yml`. Under `volumes`, declare each Hugging Face repository with its full commit SHA and the exact `files` the model opens, as paths or `**` patterns; nothing else exists at `/volumes/<name>` on the worker, and a pattern matching no file fails publication. Put structural validation in the `inputs` and `outputs` schemas; `default` is a hint for user interfaces and is never applied, so model code owns fallbacks. Keep `machine_types` in preference order and set `runtime_memory_gib` to peak host memory beyond weights, package and stack. Declare Python dependencies in `pyproject.toml`; torch and CUDA come from the stack, and the built package must stay under 2 GiB.
4. Implement `app.py`. One self-contained file holds pydantic `Input` and `Output` models, `setup(context)` loading the model from `context["volumes"]` onto `context["device"]` and returning state, `run(state, input, output_dir)` returning the output object and writing files under `output_dir`, naming them in the output by relative path, `teardown(state)` releasing the model, and the `serve()` loop itself: read a JSON line from stdin, dispatch on `command`, write one reply to descriptor 3 and flush. There is no library to install, no base class and no helper module to vendor. The scaffold and every catalog app carry the same `serve()`, so copy it unchanged instead of writing another one. An exception inside a command becomes `{"ok": false, "error": ...}` with a traceback on stderr and the loop keeps serving, so one bad request does not cost the loaded model. Input arrives exactly as submitted after schema validation. Printing to stdout or stderr is fine; both are request logs. Base weights and LoRAs are ordinary separate volumes, such as `base` and `lora`; loading them is model-specific code.
5. Run `cagoule validate DIR`, then `cagoule --json deploy DIR` for the usual remote package-and-publish workflow. For independent packaging, run `cagoule --json package app DIR --operation NAME`; it returns a job ID immediately. Poll `package status ID` and read `logs --job ID` until ready or failed. Publish its artifact URL with `package publish ARTIFACT_URL`, then inspect the app until that revision is ready or failed. `package upload ARTIFACT_DIR` uploads an existing local artifact. Use `package cancel ID` to cancel remote packaging. Publication replicates the package and synchronizes declared volumes to all regions; `volumes` and `volume ID` show replication and errors. Failed publication preserves the previous ready revision. Preflight validates against the hourly hardware catalog, not live GPU capacity or successful inference; let temporarily unavailable catalogs populate rather than launching inference to bypass validation.
6. Run a small generation against the exact ready revision using `cagoule --json run APP --revision REV --input @input.json --operation NAME --no-wait`. Reuse the operation name after an interrupted submission; choose a new one for an intentional repeat. Upload local input files with `cagoule upload`; its renewable URL is refreshed by the API on submission.
7. Poll `cagoule --json request ID`. Read `logs --job ID` for packaging failures and `logs --request ID` for runtime failures. Fix, rebuild and republish as necessary; manifest changes require a new build. Do not automatically retry inference. `cancel ID` stops a generation; `logout` only clears device login. Client interruption does not cancel cloud work: recover using job IDs, app/revision, request history and the same operation name. Packaging operation names also retain their inputs; choose a new name after changing source.
8. Return the app name, reproducible revision, request ID, result links, local files from `cagoule download`, and source location. If the source is not on the catalog's default branch, mention once that a pull request to the catalog remains, rather than treating it as part of deployment. Never put binary contents in text context.

Omit `tmp_memory_gib` for the default 4 GiB memory-backed `/tmp`. Increase it for large temporary intermediates such as decoded frames; it must stay within `runtime_memory_gib`, alongside CPU tensors and other working memory. Capacity does not preallocate RAM.

Stack names identify fixed runtime families; revisions provide compatible maintenance within a family, and apps always run on the family's current revision. Select another stack explicitly to change core runtime versions. Use remote packaging; employees need no local Python, Go, Docker or Google CLI for any of the above. Keep existing Terraform-managed models unchanged. No Terraform execution, fleet administration, private repositories, training, multi-node execution, streaming generation or promotion workflow. Gated Hugging Face repositories work when the platform's Hugging Face account has accepted their terms; if `hf inspect` reports the platform account has not been granted access, tell the user to accept the terms on huggingface.co as the platform account and retry, since the agent cannot do that itself.

`cagoule shell` provisions an ephemeral spot GPU box through the authenticated Cagoule API, carrying the stack and weights a `modelpack.yml` declares. It uses normal Cagoule sign-in and needs `ssh`, `git` and `rsync` on macOS or Linux; no Google Cloud credentials or `gcloud` are needed. The CLI generates a local SSH key under `~/.local/cagoule/ssh/` and connects directly to the box. Use `cagoule shell up` in the app directory, then `cagoule shell sync && cagoule shell ssh -- pytest src/tests`, and `cagoule shell down` when finished. Commands select the box by signed-in owner, modelpack and checkout directory. Mention it when the user is iterating on model code that needs a GPU and republishing is too slow a loop. The default lifetime is one hour; `--lifetime` overrides it. The CLI displays estimated Spot compute charges, excluding disk and network. A box bills while it runs, so start one only when the user asks and remind them to run `cagoule shell down`. Relay missing-tool or sign-in errors to the user.
